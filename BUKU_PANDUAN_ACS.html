Buku Panduan ACS

Auto Configuration Server multi-vendor (TR-069/CWMP) untuk manajemen CPE lintas merek

Versi dokumen: 2.0  ·  Tanggal: 16 Oktober 2026  ·  Audiens: Tim Operations/NOC, Administrator Tenant, Tim Jaringan (OLT), Tim Integrasi BSS/OSS

ACS ini adalah platform manajemen perangkat pelanggan (CPE — ONT/ONU/router) berbasis protokol standar Broadband Forum TR-069 (CWMP). Satu instalasi melayani banyak perusahaan (multi-tenant) dan banyak merek perangkat — ZTE, Huawei, FiberHome, Nokia, Cdata, dan vendor lain — tanpa perubahan kode, cukup penambahan data katalog.

Jawaban singkat untuk pertanyaan "config di sisi OLT atau ONT?"

ACS mengonfigurasi sisi ONT (CPE), bukan OLT. ACS berbicara langsung ke ONT lewat jaringan IP memakai protokol TR-069. ACS tidak login ke OLT, tidak mengirim perintah CLI/SNMP ke OLT, dan tidak mendaftarkan ONT di port PON. Bagian OLT (VLAN, registrasi ONT, profil bandwidth) tetap dikerjakan Tim Jaringan lewat sistem manajemen OLT. Penjelasan lengkap dengan gambar ada di Bab 1.

1 Cara kerja ACS — di OLT atau di ONT?

1.1 Jawaban singkat

Di jaringan fiber (GPON/EPON/XGS-PON) ada dua jenis perangkat yang masing-masing punya "pengelola" sendiri:

OLT — perangkat di sisi operator

Kotak di POP/central office yang melayani ratusan–ribuan ONT lewat serat PON. Dikelola oleh Tim Jaringan memakai CLI/SSH, SNMP, NETCONF, atau EMS/NMS vendor.

ACS tidak mengelola OLT.

ONT/ONU — perangkat di rumah pelanggan

Kotak kecil di rumah/kantor pelanggan: punya WiFi, port LAN, WAN (PPPoE/DHCP), dan firmware sendiri. Mendukung agen TR-069.

ACS mengelola ONT — membaca & menulis konfigurasinya.

Satu kalimat

Anggap ACS sebagai "remote control ONT lewat internet": pelanggan telepon "WiFi saya lemot/ lupa password" — NOC cukup membuka halaman perangkat itu di ACS dan mengubah SSID/password WiFi, tanpa teknisi datang dan tanpa menyentuh OLT.

1.6 Mengapa ONT yang memulai, dan bagaimana ACS "menyentil" ONT

Mayoritas ONT berada di belakang NAT/CGNAT atau firewall, sehingga ACS tidak bisa asal membuka koneksi ke ONT. Maka TR-069 dirancang ONT menghubungi ACS (keluar, biasanya port 80/443/7547 ke ACS):

  • Periodic Inform — ONT lapor tiap N detik (mis. 300–3600) walau tak ada perintah.
  • Event — ONT lapor saat boot (1 BOOT), pertama kali (0 BOOTSTRAP), nilai parameter berubah (4 VALUE CHANGE), dst.
  • Connection Request — bila NOC butuh aksi sekarang, ACS mengirim HTTP GET ke ConnectionRequestURL ONT (alamat ini ditangkap otomatis dari Inform). ONT lalu segera membuka sesi baru ke ACS. Jika ONT tak terjangkau (CGNAT), ACS mencoba fallback UDP (STUN, TR-111); jika tetap gagal, task menunggu Inform berikutnya.

1.7 Contoh nyata: mengganti password WiFi pelanggan

  1. NOC membuka Perangkat → cari serial pelanggan → tab Parameter, atau memakai Task Tulis parameter. Nilai baru dimasukkan (mis. logical key wifi.wpa_passphrase).
  2. ACS menerjemahkan logical key ke path TR-069 milik vendor/model itu lewat tabel vendor_parameter_mappings, mis. pada data model TR-098 InternetGatewayDevice.LANDevice.1.WLANConfiguration.1.PreSharedKey.1.KeyPassphrase, pada TR-181 Device.WiFi.AccessPoint.1.Security.KeyPassphrase. (Path bisa berbeda tiap vendor/firmware — itu sebabnya ada pemetaan, bukan if vendor == … di kode. Pemetaan bawaan menyasar radio utama, instance 1; path per-band/per-model ditambah lewat Katalog.)
  3. ACS membuat task SetParameterValues berstatus PENDING, lalu memicu Connection Request.
  4. ONT membuka sesi; ACS mengirim SetParameterValues; ONT menerapkan, membalas Status 0 (atau 1 bila butuh reboot).
  5. Task menjadi COMPLETED; riwayat tercatat di Timeline Audit (siapa, kapan, nilai apa — tanpa menyimpan secret di log).
Yang tidak terjadi

Tidak ada langkah di atas yang menyentuh OLT. OLT hanya meneruskan paket IP antara ACS dan ONT seperti lalu lintas data biasa.

2 Komponen & arsitektur

CWMP adalah protokol stateful berbasis sesi, bukan request-response biasa. Perangkat (CPE) yang memulai kontak — bukan ACS:

Prinsip perancangan

Perbedaan path parameter TR-069 antar vendor tidak ditangani dengan percabangan kode, melainkan lewat tabel pemetaan (vendor_parameter_mappings). Menambah dukungan vendor/model baru = operasi data, bukan rilis software. Root data model (InternetGatewayDevice.* TR-098 vs Device.* TR-181) di-resolve per perangkat, tidak diasumsikan.

3 Menjalankan ACS

  1. Salin .env.example menjadi .env dan isi: ACS_DB_ROOT_PASSWORD, ACS_DB_PASSWORD, ACS_JWT_SECRET (min. 32 karakter), ACS_CREDENTIAL_ENC_KEY (base64, 32 byte), ACS_MINIO_ACCESS_KEY, ACS_MINIO_SECRET_KEY. Untuk email: ACS_SMTP_HOST, ACS_SMTP_PORT, ACS_SMTP_USERNAME, ACS_SMTP_PASSWORD, ACS_SMTP_FROM, ACS_PUBLIC_URL. Berkas .env berisi rahasia — jangan di-commit atau dikirim lewat chat.
  2. Jalankan stack: 
    docker compose up -d        # menjalankan migrasi 0001→0024 lalu acsd
  3. Buat Superadmin pertama (sekali saja; login memakai email): 
    docker compose exec acsd /app/seed-admin \
  -username admin -password '<kata sandi kuat>' \
  -email admin@perusahaan.id -fullname "Nama Admin"
  4. Jalankan Console web: cd frontend && npm install && npm run dev, buka http://localhost:5173/login.
  5. Verifikasi: curl -s localhost:18080/api/v1/metrics membalas 200, dan POST kosong ke localhost:17547/cwmp membalas 204.
Produksi

Endpoint CWMP wajib di belakang terminasi TLS (reverse proxy) — acsd sendiri belum melayani TLS. Endpoint /api/v1/metrics tidak berautentikasi (konvensi Prometheus exporter) — firewall di level jaringan. MinIO harus reachable dari jaringan CPE fisik bila memakai strategi presigned-URL untuk firmware. Bila di belakang reverse proxy, rate limit per-IP memerlukan konfigurasi trusted proxy (belum final).

4 Login, peran, dan tenant

Detail login ada di LOGIN.md. Ringkas:

  • Login dengan email + password. Password disimpan sebagai hash Argon2id (hash lama bcrypt otomatis di-upgrade saat login berhasil).
  • Lupa password lewat email: tautan sekali pakai berlaku 30 menit; respons selalu seragam (tidak membocorkan apakah email terdaftar). Maksimum 3 permintaan per akun per jam.
  • Lockout: 5 kali salah → akun terkunci 15 menit (pemilik menerima email). Mengganti/reset password otomatis mencabut JWT lama.
  • Email notifikasi: reset, password berubah, reset oleh admin, akun terkunci, akun baru. Email tidak pernah memuat password.
  • SSO OIDC tersedia bila dikonfigurasi; akun SSO tidak punya password lokal.
PeranCakupan
SUPERADMINLintas semua tenant. Kelola tenant, katalog vendor global, firmware, kuota.
ADMINSatu tenant. Kelola user tenant sendiri, perangkat (tambah/edit/hapus/impor), provisioning, preset, branding, webhook.
NOCSatu tenant. Operasi harian: task, reboot, diagnostics, connection request, edit perangkat. Tidak menambah/menghapus perangkat atau mengubah kebijakan.
VIEWERSatu tenant, hanya baca (dan ekspor).
ENDUSERPortal pelanggan (/self-service, menu "WiFi Saya"): kelola WiFi & restart perangkat miliknya sendiri.

Tenant adalah batas isolasi data. Tiap tenant punya shared secret Inform CWMP sendiri (username/password yang diisikan ke setiap CPE milik tenant itu). Device baru yang Inform dengan secret tenant otomatis masuk ke tenant tersebut. Item global (tanpa tenant) hanya dapat diubah SUPERADMIN.

Buat tenant: Administrasi → Tenants → Tambah, atau pakai Wizard Onboarding Tenant (Administrasi → Onboarding) yang memandu: tenant + secret CWMP → admin pertama → langkah lanjutan.

5 Katalog vendor, OUI & pemetaan parameter

Menu Katalog Vendor (SUPERADMIN). Agar CPE dikenali penuh, katalog menyimpan:

  1. Vendor (ref_vendors) — terisi: ZTE, Huawei, FiberHome, Nokia, Cdata.
  2. OUI (vendor_ouis) — 6 karakter dari registri IEEE. Sudah terisi awal ±3.176 blok lewat migrasi 0022; tambah/koreksi lewat Katalog → Vendor → OUI Terdaftar atau impor CSV.
  3. Model perangkat (device_models) — opsional, untuk pemetaan spesifik per model.
  4. Pemetaan parameter (vendor_parameter_mappings) — 12 logical key standar sudah dipetakan untuk kelima vendor (nama/model/ serial/versi, SSID, passphrase WiFi, PPPoE username/password, interval inform).
Verifikasi OUI dengan Inform nyata

Data OUI berasal dari registri IEEE, tetapi belum dicocokkan dengan Inform dari CPE fisik. Saat uji lapangan, pastikan OUI dari Inform pertama ter-resolve ke vendor yang benar. Perangkat yang OUI-nya belum ada muncul sebagai "vendor belum diketahui" dan akan sembuh sendiri di Inform berikutnya setelah OUI ditambahkan.

Prosedur langkah-demi-langkah menambah vendor/model baru: lihat VENDOR_ONBOARDING.md. Seluruh tab katalog mendukung impor/ekspor (Bab 8).

7.3 Menelusuri

  • Perangkat — daftar dengan filter (vendor, status, tag, pencarian serial/MAC), seleksi massal, aksi massal (apply profile / firmware / reboot untuk banyak perangkat sekaligus).
  • Detail perangkat — tab: Parameter (tree TR-069, bisa expand/edit/AddObject/DeleteObject), Histori Event (CWMP), Task (RPC), Diagnostics, Firmware, Redaman Optik (tren RX/TX power dari ONT), Timeline Audit.
  • Ctrl/Cmd + K — command palette: cari perangkat atau lompat ke halaman mana pun.
  • Dashboard — distribusi status, perangkat per vendor, antrean task, tren redaman optik.

Memaksa perangkat lapor sekarang (Connection Request)

Detail perangkat → Connection Request (atau POST /devices/:id/connection-request). Ringkasan mekanismenya ada di §1.6. Jawaban HTTP 502 berarti "perangkat tidak dapat dihubungi" — kondisi lapangan biasa (offline/CGNAT), bukan kerusakan ACS.

Aman & bisa diulang

Kolom ekspor memakai nama yang sama dengan kolom impor, sehingga ekspor → impor ulang menghasilkan semua baris "Tidak berubah". Sel yang diawali =, +, -, @ dinetralkan agar tidak dieksekusi sebagai rumus saat dibuka di Excel (CSV injection). Rahasia tidak pernah diekspor. Batas klien: 5 MB / 5.000 baris per berkas.

9 Task: reboot, baca/tulis parameter

Semua perintah ke CPE adalah task yang mengantre di ACS dan dieksekusi saat CPE membuka sesi berikutnya (atau segera, bila dipicu Connection Request).

AksiEndpoint / UIPeran
RebootPOST /devices/:id/rebootNOC, ADMIN
Baca parameterPOST /devices/:id/tasks/get-parameter-valuesNOC, ADMIN
Tulis parameterPOST /devices/:id/tasks/set-parameter-valuesADMIN
Tambah/hapus objek.../tasks/add-object, .../tasks/delete-objectADMIN
Factory resetPOST /devices/:id/factory-resetADMIN
Retry & kegagalan

Task yang gagal karena cwmp:Fault generik di-retry hingga max_retries. Fault 9005 (Invalid Parameter Name) langsung FAILED permanen — retry pasti percuma. Fault 9003 pada GetParameterValues memicu pemecahan daftar parameter menjadi dua task. Seluruh nilai SetParameterValues saat ini dikirim bertipe xsd:string — perilaku CPE yang menuntut tipe lain perlu diuji.

10 Provisioning otomatis (Profile & Zero-Touch)

Provisioning Profile

Kumpulan parameter target (mis. SSID, kredensial PPPoE, interval inform). Dibuat di Provisioning → Profiles. Builder punya autocomplete logical key (di-resolve ke path TR-069 sesuai vendor) dengan fallback raw-path manual. Terapkan ke satu perangkat lewat Detail perangkat → Apply Profile, atau massal lewat Perangkat → seleksi → Apply Profile.

FR-18 — keputusan produk

Mengubah isi profile tidak otomatis mendorong ulang ke perangkat yang sudah terprovisioning. Ini disengaja. Untuk penegakan berkelanjutan, gunakan Preset (Bab 11).

Zero-Touch Rule (ZTP)

Provisioning → Zero-Touch Rules. Cocokkan perangkat baru berdasar OUI / serial pattern / vendor / model / versi firmware / nilai parameter, lalu jalankan aksi gabungan: apply profile dan/atau reboot dan/atau push firmware. Pilih pemicu evaluasi per rule:

  • BOOTSTRAP_ONLY — sekali, saat perangkat pertama kali dikenal.
  • BOOTSTRAP_OR_BOOT — tiap kali perangkat reboot.
  • EVERY_INFORM — pengawasan berkelanjutan (mis. "tiap inform, cek versi firmware; kalau usang, upgrade"). Ada pagar anti-loop: perangkat dengan task in-flight tidak mendapat aksi baru.

11 Preset engine (penegakan konfigurasi)

Presets (peran ADMIN). Setara "preset" GenieACS. Tiap sesi CWMP, preset dengan enforce=1 yang precondition-nya cocok akan memeriksa apakah nilai perangkat menyimpang dari target; bila menyimpang, ACS otomatis mengantre satu SetParameterValues gabungan (drift-heal). Contoh: pelanggan mengganti SSID sendiri di GUI ONT → Inform berikutnya ACS mengembalikannya ke standar operator.

Pagar bawaan: task in-flight ditunggu; cooldown 15 menit antar upaya; menyerah setelah 3 kegagalan berturut-turut (dan mencatat activity_logs agar NOC tahu). Precondition memakai kosakata yang sama dengan Zero-Touch Rule (vendor, OUI, serial pattern, versi firmware, nilai parameter).

Jitter interval inform

Bila preset/profile menyetel PeriodicInformInterval, ACS menambahkan offset deterministik per perangkat agar armada tidak Inform di detik yang sama. Nilai akhir di perangkat sengaja sedikit berbeda dari angka literal — ini fitur, bukan bug.

12 Firmware & canary rollout

  1. Upload (Superadmin): Firmware → Upload — unggah file biner sungguhan. Checksum SHA-256 dihitung di server saat streaming.
  2. Upgrade satu perangkat: Detail perangkat → Firmware → Jadwalkan. ACS mengirim RPC Download dengan presigned URL MinIO (berlaku 1 jam), ONT mengunduh lalu mengirim TransferComplete. (Yang diunduh dan diperbarui adalah firmware ONT, bukan OLT.)
  3. Canary / staged rollout (Firmware → Rollout Batches): tentukan populasi (tenant/vendor/model), persentase per wave, dan ambang failure rate. Wave berikutnya jalan otomatis hanya bila wave sebelumnya tuntas dan gagalnya di bawah ambang; bila melebihi ambang, batch PAUSED menunggu keputusan operator.
Risiko tinggi

Upgrade firmware bisa mem-brick perangkat di lokasi pelanggan. Selalu mulai dengan wave kecil (mis. 5%), ambang failure rate ketat, dan pantau sebelum melanjutkan. Jangan uji firmware ke perangkat produksi di sesi uji pertama.

13 Integrasi sistem lain (API, token, webhook)

REST API & token

  • Kontrak lengkap: openapi.yaml (OpenAPI 3.0.3, 126 operation) + ACS-API.postman_collection.json (126 request) siap impor ke Postman/Newman. Skrip scripts/api-parity.mjs memeriksa kesesuaian backend ↔ frontend.
  • Autentikasi mesin-ke-mesin: terbitkan API token di Administrasi → API Token (POST /auth/tokens). Token ber-prefix acs_, ditampilkan sekali. Kirim sebagai Authorization: Bearer acs_.... Cabut lewat DELETE /auth/tokens/:id bila bocor / karyawan resign.
  • Token & JWT sama-sama ter-scope tenant + peran. Menonaktifkan tenant langsung menolak semua token/JWT-nya pada request berikutnya.
  • Pra-registrasi massal dari sistem lain: POST /devices/import (?dry_run=true untuk pratinjau; mode skip/update).

Webhook keluar

Webhook (peran ADMIN). Daftarkan URL target untuk menerima event bertipe (mis. PARAMETER_VALUE_CHANGE, DEVICE_FAULT, TASK_FAILED) ke BSS/OSS/NMS. Payload ditandatangani; ada log pengiriman & hitung kegagalan.

15 Keamanan operasional

  • Rate limit berlapis: /auth/login 2 req/s per IP, /cwmp 5 req/s per IP, REST lainnya 30 req/s per IP. (Per-instance & per-IP — fleet di belakang CGNAT berbagi jatah; lihat LAPORAN_KESIAPAN.md.)
  • Password & sesi: Argon2id, lockout 5×/15 menit, token reset hanya disimpan sebagai hash SHA-256 (sekali pakai, 30 menit), JWT dicabut saat password berubah/akun dinonaktifkan.
  • Email: STARTTLS wajib; kredensial SMTP hanya di .env/secret manager, tidak pernah di repository. Gunakan App Password, bukan password akun; putar (rotate) bila pernah terekspos.
  • Kuota task queue per tenant (Superadmin, opsional) — membatasi task PENDING/QUEUED agar satu tenant tidak membanjiri antrean bersama.
  • Kredensial terenkripsi at-rest (AES-256-GCM): shared secret Inform tenant, kredensial connection-request per-device. Tidak pernah ditulis plaintext ke log, response API, maupun ekspor.
  • SSRF guard pada Connection Request (alamat metadata-cloud/internal ditolak).
  • Audit trail: 7 kolom audit di tabel master + feed activity_logs ("siapa mengubah apa", termasuk impor massal) + timeline per-device.
  • Backup: prosedur mariadb-dump + restore drill di PENGUJIAN_LAPANGAN.md §7. Uji restore secara berkala, bukan hanya menyimpan dump.

17.2 Batasan yang perlu diketahui

Sebelum go-live penuh
  • Uji CPE fisik belum dilakukan. Seluruh validasi alur sejauh ini memakai simulator (PENGUJIAN_E2E.md, 13/13 skenario lulus) — bukan firmware vendor sungguhan. Jalankan PENGUJIAN_LAPANGAN.md dengan minimal 1–2 unit per vendor sebelum rollout lebar.
  • CWMP dilayani via HTTP oleh acsd; TLS harus dari reverse proxy.
  • WebSocket /ws belum tersambung dari UI (backend menuntut header Bearer, browser mengirim token lewat query) — fitur realtime belum aktif.
  • Rate limit per-IP & per-instance; di belakang reverse proxy perlu trusted proxy.
  • Load test kapasitas puncak belum dilakukan (butuh rig multi-IP).
  • Ekspresivitas provisioning sengaja dibatasi ke data terstruktur (bukan skrip bebas seperti GenieACS) demi auditability.

17.3 Rencana setelah UAT: OLT Controller

Peta jalan

Pertanyaan "bisakah kita juga melihat/mengatur OLT dari satu aplikasi?" dijawab dengan modul terpisah OLT Controller — bukan perluasan ACS. Rencana: dikerjakan setelah UAT, irisan pertama ZTE (C300/C320/C600), read-only (inventori ONT, status, level optik), ditulis dengan Go native. Perintah CLI/OID tidak ditulis dari ingatan, tetapi divalidasi terhadap perangkat/ dokumentasi nyata. Dengan demikian satu konsol kelak dapat menampilkan sisi OLT dan sisi ONT, sementara ACS tetap fokus pada ONT lewat TR-069.

Rekomendasi peluncuran: mulai dengan pilot terbatas (satu anak perusahaan, populasi perangkat kecil, pemantauan ketat), bukan rollout penuh serentak ke semua tenant.
