Buku Panduan ACS

Auto Configuration Server multi-vendor (TR-069/CWMP) untuk manajemen CPE lintas merek

Versi dokumen: 1.0  ·  Tanggal: 8 September 2026  ·  Audiens: Operator NOC, Administrator Tenant, Tim Integrasi BSS/OSS

ACS ini adalah platform manajemen perangkat pelanggan (CPE — ONT/ONU/router) berbasis protokol standar Broadband Forum TR-069 (CWMP). Satu instalasi melayani banyak perusahaan (multi-tenant) dan banyak merek perangkat — ZTE, Huawei, FiberHome, Nokia, Cdata, dan vendor lain — tanpa perubahan kode, cukup penambahan data katalog.

1 Konsep dasar & komponen

CWMP adalah protokol stateful berbasis sesi, bukan request-response biasa. Perangkat (CPE) yang memulai kontak — bukan ACS:

CPE ACS │ Inform (event: BOOTSTRAP/BOOT/PERIODIC/...) → │ autentikasi shared secret, upsert inventory, │ ← InformResponse │ evaluasi Zero-Touch + Preset │ POST kosong ("siap terima perintah") → │ ambil 1 task dari antrean │ ← RPC (SetParameterValues / Reboot / Download / ...) │ jawaban RPC / cwmp:Fault → │ tandai task selesai/gagal, ambil task berikutnya │ POST kosong → │ │ ← 204 (sesi ditutup — tidak ada task lagi)
KomponenFungsiPort (dev)
Backend acsdEndpoint CWMP untuk CPE + REST API untuk operator/BSSREST 18080, CWMP 17547
MariaDBInventory, task, audit trail, katalog vendor13306
MinIOPenyimpanan file firmware (S3-compatible)19000 / konsol 19001

Frontend (Console)Antarmuka web operator — dijalankan terpisah (npm run dev, port 5173)—
Prinsip perancangan

Perbedaan path parameter TR-069 antar vendor tidak ditangani dengan percabangan kode, melainkan lewat tabel pemetaan (vendor_parameter_mappings). Menambah dukungan vendor/model baru = operasi data, bukan rilis software.

2 Menjalankan ACS

  1. Siapkan berkas .env dari .env.example — isi ACS_DB_ROOT_PASSWORD, ACS_DB_PASSWORD, ACS_JWT_SECRET (min. 32 karakter), ACS_CREDENTIAL_ENC_KEY (base64, 32 byte), ACS_MINIO_ACCESS_KEY, ACS_MINIO_SECRET_KEY.
  2. Jalankan stack: 
    docker compose up -d        # menjalankan migrasi 0001→0021 lalu acsd
  3. Buat Superadmin pertama (sekali saja): 
    docker compose exec acsd /app/seed-admin \
  -username admin -password '<kata sandi kuat>' -email admin@perusahaan.id
  4. Verifikasi: curl -s localhost:18080/api/v1/metrics membalas 200, dan POST kosong ke localhost:17547/cwmp membalas 204.
Produksi

Endpoint CWMP wajib di belakang terminasi TLS (reverse proxy). Endpoint /api/v1/metrics tidak berautentikasi (konvensi Prometheus exporter) — firewall di level jaringan. MinIO harus reachable dari jaringan CPE fisik bila memakai strategi presigned-URL untuk firmware.

3 Login, peran, dan tenant

Detail lengkap alur login, SSO/OIDC, akun terkunci, dan pemecahan masalah login ada di PANDUAN_LOGIN_ACS.pdf. Ringkas:

PeranCakupan
SUPERADMINLintas semua tenant. Kelola tenant, katalog vendor global, firmware, kuota.
ADMINSatu tenant. Kelola user tenant sendiri, provisioning, preset, branding, webhook.
NOCSatu tenant. Operasi harian: task, reboot, diagnostics, connection request. Tidak mengubah konfigurasi kebijakan.
VIEWERSatu tenant, hanya baca.
ENDUSERPortal pelanggan (/self-service): kelola WiFi & restart perangkat miliknya sendiri.

Tenant adalah batas isolasi data. Tiap tenant punya shared secret Inform CWMP sendiri (username/password yang diisikan ke setiap CPE milik tenant itu). Device baru yang Inform dengan secret tenant otomatis masuk ke tenant tersebut.

Buat tenant: Administration → Tenants → Tambah, atau pakai Wizard Onboarding Tenant (Administration → Onboarding) yang memandu: tenant + secret CWMP → admin pertama → langkah lanjutan.

4 Onboarding vendor & OUI

Sebelum CPE sebuah vendor bisa dikenali penuh, katalog perlu tahu:

  1. Vendor (ref_vendors) — sudah terisi: ZTE, Huawei, FiberHome, Nokia, Cdata.
  2. OUI (vendor_ouis) — 6 digit heksadesimal dari IEEE OUI registry. Belum terisi — wajib diisi per vendor sebelum uji lapangan (lihat callout).
  3. Model perangkat (device_models) — opsional, untuk pemetaan spesifik per model.
  4. Pemetaan parameter (vendor_parameter_mappings) — 12 logical key standar sudah dipetakan untuk kelima vendor (nama/model/ serial/versi, SSID, passphrase WiFi, PPPoE username/password, interval inform).
Wajib sebelum uji lapangan

vendor_ouis masih kosong. Setiap CPE yang Inform akan muncul sebagai "vendor belum diketahui" sampai OUI-nya didaftarkan. Ini bukan kegagalan — segera tambahkan OUI perangkat lewat Catalog → Vendors → OUI Terdaftar begitu MAC address-nya terlihat. Satu digit OUI salah bisa membuat perangkat ter-assign ke vendor yang keliru — verifikasi dari registri IEEE, jangan dari ingatan.

Prosedur langkah-demi-langkah menambah vendor/model baru: lihat VENDOR_ONBOARDING.md.

5 Menghubungkan CPE ke ACS

Di GUI/CLI tiap CPE, isi bagian TR-069 / ACS / Remote Management:

Field CPEIsi dengan
ACS URLhttps://acs.perusahaan.id/cwmp (dev: http://<ip>:17547/cwmp)
ACS Username / Passwordshared secret Inform tenant (dari Administration → Tenants → Kredensial CWMP)
Periodic Inform Enabletrue
Periodic Inform Interval300–3600 detik (ACS menambahkan jitter otomatis untuk mencegah lonjakan serempak)

Setelah tersimpan, CPE akan mengirim Inform 1 BOOT atau 0 BOOTSTRAP. Dalam beberapa detik perangkat muncul di Devices. ConnectionRequestURL perangkat di-capture otomatis dari Inform — operator tidak perlu mengisinya manual agar bisa memicu Connection Request.

6 Melihat & menelusuri perangkat

  • Devices — daftar dengan filter (vendor, status, tag, pencarian serial/MAC), seleksi massal, dan aksi massal (apply profile / firmware / reboot untuk banyak perangkat sekaligus).
  • Device Detail — tab: Parameter (tree TR-069, bisa expand/edit/AddObject/DeleteObject), Histori Event (CWMP), Task (RPC), Diagnostics, Firmware, Redaman Optik (tren RX/TX power), Timeline Audit (siapa mengubah apa).
  • Ctrl/Cmd + K — command palette: cari perangkat atau lompat ke halaman mana pun.
  • Dashboard — distribusi status, perangkat per vendor, antrean task, tren redaman optik.

Memaksa perangkat lapor sekarang (Connection Request)

Device Detail → Connection Request (atau POST /devices/:id/connection-request). ACS menghubungi CPE agar segera membuka sesi, tanpa menunggu periodic inform. Bila CPE offline / di balik CGNAT, ACS mencoba fallback UDP (STUN/TR-111); bila tetap gagal, jawaban HTTP 502 berarti "perangkat tidak dapat dihubungi" — kondisi lapangan biasa, bukan kerusakan ACS.

7 Task: reboot, baca/tulis parameter

Semua perintah ke CPE adalah task yang mengantre di ACS dan dieksekusi saat CPE membuka sesi berikutnya (atau segera, bila dipicu Connection Request).

AksiEndpoint / UIPeran
RebootPOST /devices/:id/rebootNOC, ADMIN
Baca parameterPOST /devices/:id/tasks/get-parameter-valuesNOC, ADMIN
Tulis parameterPOST /devices/:id/tasks/set-parameter-valuesADMIN
Tambah/hapus objek.../tasks/add-object, .../tasks/delete-objectADMIN
Factory resetPOST /devices/:id/factory-resetADMIN
Retry & kegagalan

Task yang gagal karena cwmp:Fault generik di-retry hingga max_retries. Fault 9005 (Invalid Parameter Name) langsung FAILED permanen — retry pasti percuma. Fault 9003 pada GetParameterValues memicu pemecahan daftar parameter menjadi dua task.

8 Provisioning otomatis (Profile & Zero-Touch)

Provisioning Profile

Kumpulan parameter target (mis. SSID, kredensial PPPoE, interval inform). Dibuat di Provisioning → Profiles. Builder punya autocomplete logical key (di-resolve ke path TR-069 sesuai vendor) dengan fallback raw-path manual. Terapkan ke satu perangkat lewat Device Detail → Apply Profile, atau massal lewat Devices → seleksi → Apply Profile.

FR-18 — keputusan produk

Mengubah isi profile tidak otomatis mendorong ulang ke perangkat yang sudah terprovisioning. Ini disengaja. Untuk penegakan berkelanjutan, gunakan Preset (bagian 9).

Zero-Touch Rule (ZTP)

Provisioning → Zero-Touch Rules. Cocokkan perangkat baru berdasar OUI / serial pattern / vendor / model / versi firmware / nilai parameter, lalu jalankan aksi gabungan: apply profile dan/atau reboot dan/atau push firmware. Pilih pemicu evaluasi per rule:

  • BOOTSTRAP_ONLY — sekali, saat perangkat pertama kali dikenal.
  • BOOTSTRAP_OR_BOOT — tiap kali perangkat reboot.
  • EVERY_INFORM — pengawasan berkelanjutan (mis. "tiap inform, cek versi firmware; kalau usang, upgrade"). Ada pagar anti-loop: perangkat dengan task in-flight tidak mendapat aksi baru.

9 Preset engine (penegakan konfigurasi)

Presets (peran ADMIN). Setara "preset" GenieACS. Tiap sesi CWMP, preset dengan enforce=1 yang precondition-nya cocok akan memeriksa apakah nilai perangkat menyimpang dari target; bila menyimpang, ACS otomatis mengantre satu SetParameterValues gabungan (drift-heal).

Pagar bawaan: task in-flight ditunggu; cooldown 15 menit antar upaya; menyerah setelah 3 kegagalan berturut-turut (dan mencatat activity_logs agar NOC tahu). Precondition memakai kosakata yang sama dengan Zero-Touch Rule (vendor, OUI, serial pattern, versi firmware, nilai parameter).

Jitter interval inform

Bila preset/profile menyetel PeriodicInformInterval, ACS menambahkan offset deterministik per perangkat agar armada tidak Inform di detik yang sama. Nilai akhir di perangkat sengaja sedikit berbeda dari angka literal — ini fitur, bukan bug.

10 Firmware & canary rollout

  1. Upload (Superadmin): Firmware → Upload — unggah file biner sungguhan. Checksum SHA-256 dihitung di server saat streaming.
  2. Upgrade satu perangkat: Device Detail → Firmware → Jadwalkan. ACS mengirim RPC Download dengan presigned URL MinIO (berlaku 1 jam), perangkat mengunduh lalu mengirim TransferComplete.
  3. Canary / staged rollout (Firmware → Rollout Batches): tentukan populasi (tenant/vendor/model), persentase per wave, dan ambang failure rate. Wave berikutnya jalan otomatis hanya bila wave sebelumnya tuntas dan gagalnya di bawah ambang; bila melebihi ambang, batch PAUSED menunggu keputusan operator.
Risiko tinggi

Upgrade firmware bisa mem-brick perangkat di lokasi pelanggan. Selalu mulai dengan wave kecil (mis. 5%), ambang failure rate ketat, dan pantau sebelum melanjutkan. Jangan uji firmware ke perangkat produksi di sesi uji pertama.

11 Integrasi sistem lain (API, token, webhook)

REST API & token

  • Kontrak lengkap: openapi.yaml (OpenAPI 3.0.3, 103 operation) + ACS-API.postman_collection.json siap impor ke Postman/Newman.
  • Autentikasi mesin-ke-mesin: terbitkan API token di Administration → API Token (POST /auth/tokens). Token ber-prefix acs_, ditampilkan sekali. Kirim sebagai Authorization: Bearer acs_.... Cabut lewat DELETE /auth/tokens/:id bila bocor / karyawan resign.
  • Token & JWT sama-sama ter-scope tenant + peran. Menonaktifkan tenant langsung menolak semua token/JWT-nya pada request berikutnya.

Webhook keluar

Webhooks (peran ADMIN). Daftarkan URL target untuk menerima event bertipe (mis. PARAMETER_VALUE_CHANGE, DEVICE_FAULT, TASK_FAILED) ke BSS/OSS/NMS. Payload ditandatangani; ada log pengiriman & hitung kegagalan.

13 Keamanan operasional

  • Rate limit berlapis: /auth/login 2 req/s per IP, /cwmp 5 req/s per IP, REST lainnya 30 req/s per IP.
  • Proteksi brute-force: 5 login gagal berturut-turut → akun terkunci 15 menit (pesan error disamarkan dengan "password salah" biasa).
  • Kuota task queue per tenant (Superadmin, opsional) — membatasi task PENDING/QUEUED agar satu tenant tidak membanjiri antrean bersama.
  • Kredensial terenkripsi at-rest (AES-256-GCM): shared secret Inform tenant, kredensial connection-request per-device. Tidak pernah ditulis plaintext ke log atau response API.
  • Audit trail: 7 kolom audit di tabel master + feed activity_logs ("siapa mengubah apa") + timeline per-device.
  • Backup: prosedur mariadb-dump + restore drill di PENGUJIAN_LAPANGAN.md §7. Uji restore secara berkala, bukan hanya menyimpan dump.

14 Pemecahan masalah

GejalaKemungkinan penyebab & tindakan
Perangkat tidak muncul di DevicesInform ditolak (secret salah / tenant nonaktif) — cek log acsd untuk Inform ditolak (unauthorized). Pastikan ACS URL & secret di CPE benar, port CWMP reachable dari VLAN CPE.
Perangkat muncul "vendor belum diketahui"OUI belum terdaftar. Tambahkan di Catalog → Vendors → OUI. Assign vendor_id manual untuk perangkat yang sudah kadung dibuat.
Task PENDING tidak pernah terkirimPerangkat belum membuka sesi baru. Picu Connection Request. Bila 502, perangkat memang tidak dapat dihubungi (offline/CGNAT).
SetParameterValues gagal 9005Path parameter tidak ada di perangkat itu (beda per vendor/firmware). Cek pemetaan vendor_parameter_mappings untuk model tersebut.
HTTP 429Rate limit. Untuk integrasi, sebar beban; jangan burst.
HTTP 401 "token ditolak" mendadak untuk semua user satu tenantTenant dinonaktifkan. Aktifkan kembali via Administration → Tenants.
Rollout batch PAUSEDFailure rate wave melebihi ambang, atau 0 perangkat berhasil dijadwalkan (kuota task queue penuh). Periksa activity_logs, perbaiki penyebab, lalu Advance manual.

Untuk diagnosis gejala CPE yang lebih dalam (rantai Inform → sesi → task → pemetaan parameter), gunakan panduan diagnostik di PENGUJIAN_LAPANGAN.md §2 yang membedakan bug asli dari batasan yang sudah diketahui.

15 Batasan yang perlu diketahui

Sebelum go-live penuh
  • Uji CPE fisik belum dilakukan. Seluruh validasi alur sejauh ini memakai simulator (lihat PENGUJIAN_E2E.md, 9/9 skenario lulus) — bukan firmware vendor sungguhan. Jalankan PENGUJIAN_LAPANGAN.md dengan minimal 1–2 unit per vendor sebelum rollout lebar.
  • vendor_ouis masih kosong untuk kelima vendor.
  • Load test kapasitas puncak belum dilakukan — rate limiter /cwmp membatasi pengukuran dari satu IP. Butuh rig multi-IP untuk angka "ribuan sesi concurrent".
  • USP / TR-369 baru kerangka — belum operasional.
  • Ekspresivitas provisioning sengaja dibatasi ke data terstruktur (bukan skrip bebas seperti GenieACS) demi auditability.

Rekomendasi peluncuran: mulai dengan pilot terbatas (satu anak perusahaan, populasi perangkat kecil, pemantauan ketat), bukan rollout penuh serentak ke semua tenant.
