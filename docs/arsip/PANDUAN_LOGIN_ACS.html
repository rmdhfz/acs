Panduan Login ACS Console

Cara masuk ke dashboard ACS, membuat akun pertama, mengelola kata sandi, dan mengatasi kendala login.

Untuk: Operator NOC, Admin Tenant, Superadmin Platform  ·  Versi dokumen: 2026-09-03  ·  Berlaku untuk: ACS Console (frontend React) + REST API /api/v1

1.Sekilas: apa yang Anda butuhkan

ACS Console adalah antarmuka web untuk memantau dan mengelola perangkat CPE (ONT/ONU/router) lewat protokol TR-069. Untuk bisa login Anda memerlukan tiga hal:

Komponen Alamat (lingkungan dev) Keterangan
Halaman Console (frontend) http://localhost:5173/login Yang Anda buka di browser. Di produksi: domain perusahaan, mis. https://acs.perusahaan.com/login.
REST API (backend acsd) http://localhost:18080/api/v1 Console memanggil API ini saat login. Harus hidup & reachable dari browser Anda.
Akun pengguna — Username + kata sandi yang valid dan berperan (role). Lihat bagian 3 bila belum punya.
Catatan lingkungan

Di development, backend dijalankan lewat Docker Compose (docker compose up -d) dan frontend dijalankan terpisah dengan npm run dev. Alamat API yang dipakai frontend diatur di file frontend/.env pada baris VITE_API_BASE_URL.

Di produksi, frontend adalah hasil npm run build yang di-serve satu domain dengan API di belakang reverse proxy (lihat RUNBOOK.md). URL login mengikuti domain tersebut.

2.Langkah login

  1. Pastikan backend berjalan. Di lingkungan dev: jalankan docker compose ps dan pastikan service acsd berstatus Up. Pastikan juga frontend berjalan (npm run dev di folder frontend/).
  2. Buka browser ke halaman login, mis. http://localhost:5173/login.
  3. Isi kolom Username dan Password. Gunakan ikon mata di kolom password untuk menampilkan/menyembunyikan yang Anda ketik.
  4. Klik tombol Masuk. Tombol berubah menjadi “Memeriksa…” selama proses berlangsung.
  5. Bila berhasil, Anda diarahkan otomatis:
    • Peran staf (Superadmin / Admin / NOC / Viewer) → halaman Dashboard.
    • Peran pelanggan (ENDUSER) → halaman Perangkat Saya (portal self-service).

Sesi login berlaku 8 jam (dapat dikonfigurasi lewat ACS_JWT_EXPIRY). Setelah itu Anda akan diminta login ulang. Token disimpan di penyimpanan lokal browser — jangan login di komputer publik/bersama, dan gunakan tombol Logout (ikon di pojok kiri bawah, di samping nama Anda) saat selesai.

Login lewat SSO (bila tersedia)

Jika organisasi Anda sudah mengaktifkan Single Sign-On (OIDC), gunakan tombol Masuk dengan SSO di bawah form. Tombol ini selalu terlihat, tetapi hanya berfungsi bila operator sudah mengisi konfigurasi ACS_OIDC_* di backend. Bila belum dikonfigurasi, tombol akan menghasilkan halaman “tidak ditemukan” — gunakan login username/password biasa.

3.Belum punya akun, atau lupa kata sandi Superadmin

ACS tidak punya pendaftaran mandiri. Akun dibuat oleh Admin/Superadmin dari menu Administration → Users. Untuk instalasi baru (atau bila semua kata sandi Superadmin hilang), buat akun Superadmin pertama lewat perintah seed-admin yang sudah disertakan.

A. Bila backend berjalan di Docker Compose

# dijalankan dari folder root proyek, saat "docker compose up" aktif
docker compose exec acsd /app/seed-admin \
  -username admin_baru \
  -password "KataSandiKuat123" \
  -email admin_baru@perusahaan.com

B. Bila menjalankan backend langsung dengan Go (tanpa Docker)

# perlu variabel lingkungan DB yang sama dengan acsd (mis. dari file .env)
go run ./cmd/seed-admin \
  -username admin_baru \
  -password "KataSandiKuat123" \
  -email admin_baru@perusahaan.com

Setelah perintah selesai (menampilkan superadmin "admin_baru" dibuat (id=...)), langsung login di Console memakai username dan kata sandi tersebut.

Aturan kata sandi

Minimal 8 karakter. Perintah seed-admin hanya untuk akun Superadmin pertama; akun berikutnya dibuat lewat UI Administration → Users oleh akun yang sudah punya peran Admin/Superadmin.

4.Peran (role) dan hak akses

Setiap akun punya satu peran atau lebih. Peran menentukan menu apa yang muncul dan aksi apa yang diizinkan.

Peran Cakupan Yang bisa dilakukan
SUPERADMIN Seluruh tenant (lintas perusahaan) Semua. Kelola tenant, katalog vendor global, mapping parameter, semua user & perangkat.
ADMIN Satu tenant Kelola user & peran di tenant sendiri, provisioning profile, zero-touch rule, preset, firmware, branding, webhook.
NOC Satu tenant Operasional: lihat status perangkat, reboot, connection request, diagnostik (ping/traceroute), kelola tag perangkat, batalkan task.
VIEWER Satu tenant Hanya baca: dashboard, daftar perangkat, task, log — tanpa tombol aksi.
ENDUSER Perangkat milik sendiri Portal pelanggan: ubah SSID/kata sandi WiFi dan restart perangkat sendiri. Tidak bisa membuka dashboard.

5.Mengelola kata sandi

Admin/Superadmin mereset kata sandi user lain

  1. Buka Administration → Users.
  2. Pada baris user yang bersangkutan, klik Reset Password.
  3. Masukkan kata sandi baru (minimal 8 karakter) dan simpan. Sampaikan kata sandi ini ke pengguna lewat jalur aman.

Mereset kata sandi otomatis membuka kunci akun yang sedang terkunci (lihat bagian 6).

Mengganti kata sandi sendiri

Setelah login, klik ikon kunci di pojok kiri bawah (di samping nama Anda dan tombol Logout), lalu isi kata sandi lama dan kata sandi baru. Tersedia untuk semua peran.

Alternatif via API bila diperlukan otomasi: 

# ganti <TOKEN> dengan access_token dari respons login
curl -X PATCH http://localhost:18080/api/v1/auth/password \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"current_password":"lama","new_password":"BaruMinimal8"}'

6.Akun terkunci karena gagal login

Sebagai proteksi brute-force, akun akan terkunci selama 15 menit setelah 5 kali kata sandi salah berturut-turut.

Pesan error sengaja disamarkan

Saat akun terkunci, pesan yang muncul tetap “username atau password salah” — persis sama dengan kata sandi keliru biasa. Ini disengaja agar penyerang tidak tahu akun mana yang valid. Jadi bila Anda yakin kata sandi benar tetapi tetap ditolak, kemungkinan besar akun sedang terkunci.

Solusi:

  • Tunggu 15 menit, lalu coba lagi — kunci lepas otomatis; atau
  • Minta Admin/Superadmin melakukan Reset Password (langsung membuka kunci).

Selain itu, endpoint login dibatasi 2 permintaan per detik per alamat IP. Bila banyak orang login dari satu IP publik (mis. di balik NAT kantor) dalam waktu bersamaan, sebagian bisa mendapat error “terlalu banyak permintaan” (HTTP 429) — tunggu beberapa detik lalu ulangi.

7.Tenant dinonaktifkan

Bila Superadmin menonaktifkan tenant tempat akun Anda berada, login ditolak dengan pesan spesifik “tenant tidak aktif, hubungi administrator”. Sesi yang sedang berjalan pun langsung berhenti pada permintaan berikutnya (tidak menunggu token kedaluwarsa). Hubungi Superadmin platform untuk mengaktifkan kembali tenant Anda.

8.Pemecahan masalah

Gejala Kemungkinan sebab & solusi
Halaman login tidak terbuka sama sekali Frontend belum berjalan. Jalankan npm run dev di folder frontend/, buka port yang ditampilkannya (biasanya 5173).
Muncul “Gagal login, coba lagi” atau error jaringan di form Console tidak bisa menghubungi API. Cek: (a) docker compose ps — service acsd harus Up; (b) nilai VITE_API_BASE_URL di frontend/.env menunjuk ke alamat yang benar (default http://localhost:18080/api/v1); (c) coba buka http://localhost:18080/api/v1/metrics di browser — harus memuat teks metrik.
Selalu “username atau password salah” padahal yakin benar (a) Caps Lock aktif; (b) akun terkunci — tunggu 15 menit atau minta reset (bagian 6); (c) username salah ketik (perhatikan huruf besar/kecil). Bila tetap gagal, buat/reset akun lewat seed-admin atau Admin.
Setelah login langsung dilempar kembali ke halaman login Token ditolak backend. Biasanya karena jam sistem server menyimpang jauh, atau ACS_JWT_SECRET di backend berubah setelah token diterbitkan. Login ulang; bila masih terjadi, hubungi tim infrastruktur.
Error CORS di konsol browser (F12) Origin frontend belum diizinkan backend. Tambahkan URL frontend ke daftar ACS_CORS_ALLOW_ORIGINS pada environment acsd, lalu restart backend.
HTTP 429 saat login Rate limit login (2 req/detik per IP) terpicu. Tunggu beberapa detik dan coba lagi.
Butuh bantuan lebih lanjut

Detail menjalankan & men-deploy sistem ada di RUNBOOK.md. Referensi endpoint API lengkap ada di openapi.yaml (dapat dibuka di Swagger UI / Redoc) dan koleksi ACS-API.postman_collection.json.
