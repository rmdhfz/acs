Pengujian Lapangan ACS

Persiapan jaringan, prosedur uji CPE fisik multi-vendor, dan pembagian tanggung jawab tim

Versi: 1.0  ·  Tanggal: 8 September 2026  ·  Untuk: Tim Network, Tim NOC/ACS, Koordinator Uji

Dokumen ini menyiapkan uji lapangan pertama ACS ke CPE fisik (ZTE, Huawei, FiberHome, Nokia, Cdata). Sampai saat ini seluruh validasi alur memakai simulator (9/9 skenario e2e lulus) — belum ada satu Inform pun dari perangkat fisik. Tujuan sesi ini: membuktikan interoperabilitas protokol & pemetaan parameter dengan firmware vendor sungguhan.

Untuk uji lab sederhana

Bila ACS dan CPE berada di satu segmen L2 yang sama dan memakai HTTP polos (tanpa proxy TLS), CPE cukup diarahkan ke http://<IP-ACS>:7547/cwmp langsung. Reverse proxy + TLS tetap wajib untuk produksi (TR-069 mengangkut kredensial).

3 Yang perlu disiapkan — Tim Network

3.1 Firewall & routing

#Sumber → TujuanPort / ProtokolAlasan
N1Segmen CPE → ACS (proxy)TCP 443 (atau 7547 utk lab HTTP)CPE mengirim Inform ke ACS. Tanpa ini device tidak akan pernah muncul.
N2ACS (acsd) → Segmen CPETCP 7547 (default) / UDP utk STUNConnection Request: ACS memaksa CPE Inform segera. Port di sisi CPE bervariasi (7547 / 30005) — cek per model.
N3Segmen CPE → MinIO/object storageTCP 443CPE mengunduh file firmware via presigned URL. Hanya perlu bila menguji fitur firmware.
N4Segmen NOC → ACS (proxy)TCP 443Operator membuka ACS Console.
N5Sistem BSS → ACS (proxy)TCP 443Integrasi REST API + penerimaan webhook (opsional untuk uji pertama).
N6acsd → MariaDB / Redis / MinIOTCP 3306 / 6379 / 9000Internal zona data — biasanya sudah 1 host (docker-compose) saat uji.
Titik gagal paling umum

N1 (CPE tidak bisa mencapai ACS) dan N2 (ACS tidak bisa balik ke CPE). Uji keduanya sebelum hari-H: dari host di segmen CPE, curl -v telnet://<IP-ACS>:7547; dari host ACS, curl -v telnet://<IP-CPE>:7547. Jangan mendiagnosa ini di tengah sesi uji.

3.2 DNS

  • Satu FQDN untuk ACS, mis. acs.perusahaan.id, resolve ke IP reverse proxy — dari segmen CPE dan dari segmen NOC. CPE menyimpan URL ini permanen; ganti IP tanpa DNS = re-provisioning manual semua CPE.
  • Bila memakai presigned URL MinIO: host MinIO juga harus resolvable & reachable dari segmen CPE (bukan hanya dari ACS).

3.3 TLS (produksi — untuk lab HTTP boleh dilewati)

  • Sertifikat valid (bukan self-signed) pada FQDN ACS di reverse proxy — banyak firmware CPE menolak sertifikat yang tidak tepercaya pada endpoint ACS.
  • Terminasi TLS di proxy; proxy meneruskan X-Forwarded-For agar ACS melihat IP CPE yang sebenarnya (dipakai untuk validasi Connection Request anti-SSRF: URL CR harus se-host dengan IP Inform).

3.4 Rencana pengalamatan IP

  • IP statis / reservasi DHCP untuk server ACS.
  • Daftar IP CPE yang akan diuji (untuk uji reachability N2 & mencocokkan di log). Bila CPE di belakang NAT/CGNAT, catat — Connection Request HTTP langsung tidak akan bekerja; fallback STUN/UDP belum teruji lapangan (§11).

4 Yang perlu disiapkan — Tim NOC/ACS

  • Stack ACS berjalan & sehat: docker compose up -d, lalu curl -s localhost:8080/api/v1/metrics → 200 dan POST kosong ke :7547/cwmp → 204.
  • Migrasi database 0001→0021 jalan bersih (otomatis saat up).
  • Backup database sebelum sesi (§13 punya perintahnya).
  • Buat tenant pilot khusus (Administration → Tenants) — jangan pakai tenant yang sudah berisi data lain.
  • Set shared secret Inform CWMP tenant pilot (tombol "Kredensial CWMP") — catat username & password, minimal 16 karakter.
  • Siapkan akun operator: 1 SUPERADMIN + 1 ADMIN/NOC untuk tenant pilot.
  • Siapkan daftar OUI (6 digit heksadesimal, dari IEEE registry) untuk tiap vendor yang akan diuji — vendor_ouis masih kosong (§11).
  • Buka log acsd real-time selama sesi: docker compose logs -f acsd — cari cwmp: Inform diterima dan Inform ditolak (unauthorized).

5 Yang perlu disiapkan — per perangkat CPE

  • Minimal 1 unit per vendor (boleh bertahap, tidak harus kelimanya di hari yang sama). Unit yang boleh gagal/reboot — jangan unit pelanggan aktif.
  • Akses admin GUI/CLI tiap CPE (untuk mengisi ACS URL).
  • Catat MAC address & serial number tiap unit sebelum mulai — untuk dicocokkan di daftar Devices.
  • Catat model persis & versi firmware tiap unit.
  • Koneksi WAN aktif di tiap CPE (agar bisa menjangkau ACS).

6 Cara kerja sesi CWMP (referensi)

CWMP adalah protokol stateful berbasis sesi — CPE yang memulai. Memahami ini penting saat mendiagnosa "kenapa task tidak jalan".

sequenceDiagram
  autonumber
  participant C as CPE
  participant P as Reverse Proxy
  participant A as acsd
  participant D as MariaDB

  C->>P: HTTPS POST — Inform (Basic Auth, event 0 BOOTSTRAP)
  P->>A: teruskan :7547
  A->>D: validasi shared secret tenant
  A->>D: upsert device + catat event + sesi
  A->>A: evaluasi Zero-Touch + Preset
  A-->>C: 200 InformResponse (Set-Cookie: sesi)
  C->>A: POST kosong ("siap terima perintah")
  A->>D: ambil 1 task dari antrean
  A-->>C: RPC — SetParameterValues / Reboot / Download
  C->>A: jawaban RPC  atau  cwmp:Fault
  A->>D: tandai task COMPLETED / FAILED
  A-->>C: task berikutnya  atau  204 (sesi ditutup)
  Note over C,A: Task hanya terkirim SAAT sesi terbuka.
Connection Request memaksa CPE membuka sesi tanpa menunggu Periodic Inform.

10 Prosedur uji per perangkat

Ulangi untuk tiap unit. Jangan lompat langkah — kalau langkah N gagal, hentikan di situ supaya jelas titik masalahnya.

Tidak ada log sama sekali → N1 (reachability). Salah tenant → secret milik tenant lain.

11 Batasan yang sudah diketahui

Ini bukan bug baru kalau ditemukan di lapangan:

  • vendor_ouis kosong untuk kelima vendor — device baru selalu muncul "Vendor belum diketahui" sampai OUI didaftarkan.
  • Logical key yang sudah dipetakan (semua vendor, TR-098 & TR-181): manufacturer, model, serial, hardware/software version, uptime, periodic inform interval, connection request URL, WiFi SSID, WiFi passphrase, PPPoE username/password — semua asumsi instance pertama (.1).
  • Belum dipetakan (jangan kaget kalau tidak ada di provisioning profile): split SSID 2.4G/5G, WAN IP address, optical power RX/TX (selalu vendor extension nonstandar X_<OUI>_...).
  • STUN/CGNAT: ada fallback UDP TR-111 tapi belum teruji ke CGNAT nyata. CPE di belakang NAT berlapis + Connection Request gagal = belum tentu bug.
  • Firmware upgrade end-to-end ke perangkat fisik belum pernah dilakukan.
  • Dark mode & tampilan mobile Console belum diverifikasi visual di browser sungguhan.

12 Yang tidak dicoba di sesi pertama

  • Firmware upgrade ke perangkat pelanggan aktif — hanya unit yang boleh brick.
  • Push kredensial PPPoE pelanggan asli — pakai dummy sampai path parameter terbukti cocok.
  • Bulk actions ke banyak device — satu-satu dulu agar jelas device mana yang bermasalah.
  • Preset enforce=1 di tenant produksi — bikin task otomatis.

13 Pelaporan temuan

Untuk tiap device catat: vendor, model persis, versi firmware, hasil tiap langkah §10 (berhasil/gagal/skip + catatan), path TR-069 yang berbeda dari yang dipetakan, OUI yang belum terdaftar, screenshot/log untuk perilaku tak terduga.

Backup database (jalankan sebelum sesi)

docker compose exec mariadb sh -c 'mariadb-dump -uacs -p"$MARIADB_PASSWORD" acs' \
  > backup_sebelum_uji_$(date +%Y%m%d).sql

Restore (bila data berantakan)

docker compose exec -T mariadb sh -c 'mariadb -uacs -p"$MARIADB_PASSWORD" acs' \
  < backup_sebelum_uji_YYYYMMDD.sql

15 Checklist kesiapan (Go / No-Go)

Semua harus tercentang sebelum sesi dimulai:

  • Network: reachability CPE→ACS :443/:7547 terbukti dari host di segmen CPE
  • Network: reachability ACS→CPE :7547 terbukti dari host ACS
  • Network: FQDN ACS resolve dari segmen CPE & NOC
  • Network: (produksi) sertifikat TLS valid, X-Forwarded-For diteruskan proxy
  • NOC/ACS: /api/v1/metrics → 200, POST kosong /cwmp → 204
  • NOC/ACS: backup database sudah dibuat & diverifikasi ukurannya wajar
  • NOC/ACS: tenant pilot dibuat, shared secret dicatat
  • NOC/ACS: daftar OUI per vendor sudah disiapkan (dari IEEE)
  • NOC/ACS: docker compose logs -f acsd terbuka di layar monitor
  • Field: ≥ 1 unit CPE per vendor, MAC/serial/firmware tercatat, WAN aktif
  • Field: akses admin GUI tiap CPE tersedia
  • Koordinator: lembar pelaporan §13 siap, RACI dikomunikasikan
No-Go bila

Reachability N1 atau N2 belum terbukti — sesi akan habis untuk debugging jaringan, bukan menguji ACS. Tunda sampai tim Network mengkonfirmasi kedua arah.
