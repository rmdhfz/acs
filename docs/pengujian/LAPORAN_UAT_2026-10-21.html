1. Kesimpulan

Layak melanjutkan UAT dengan syarat — belum layak dinyatakan lulus penuh. Jalur inti CWMP (ONT terhubung → ACS membaca konfigurasi → ACS mengubah konfigurasi) terbukti pada ONT nyata, termasuk satu bug protokol yang hanya muncul di firmware asli dan sudah diperbaiki. Namun yang terbukti menulis ke ONT baru SSID dan password pada ZTE F660 serta reboot; redaman optik ZTE, uji tulis lanjutan (aktif/nonaktif, Hide, Max Clients), dan uji tulis pada F609 serta Optictimes belum dilakukan. Lingkungan uji juga belum dipulihkan (lihat bagian 6).

Temuan yang paling penting

  • T-07 — Fault 9002 pada SetParameterValues (ZTE F660). Akar masalah: pustaka XML menulis atribut tipe sebagai _XMLSchema-instance:type; firmware ketat menolaknya. Diperbaiki menjadi xsi:type literal, lulus di e2e dan di ONT nyata. Pelajaran: XML yang sah secara namespace belum tentu diterima firmware.
  • T-14 — Ketiga ONT masih diarahkan ke ACS ini. ACS Telkom tidak mengelolanya selama itu; harus dikembalikan sebelum UAT ditutup.
  • T-03 — Windows Firewall dimatikan total selama uji. Harus dinyalakan lagi dengan rule khusus TCP 17547.
  • T-12 — Password WiFi tersimpan plaintext di database untuk task. Task baru kini dienkripsi; task lama belum di-backfill.

4. Perbaikan dan fitur yang diselesaikan hari ini

32 commit terarah di cabang dev (belum di-push). Pengelompokan:

  • Protokol: xsi:type literal; ParameterKey ≤ 32 karakter; rincian fault per parameter di pesan error task; Connection Request otomatis di balik NAT (opt-in ACS_CR_TRUSTED_CIDRS, tetap anti-SSRF); nilai rahasia task dienkripsi; log WARN "unauthorized" yang berisik dihilangkan.
  • Console — perangkat: tab WiFi lengkap (semua SSID, klien, aktif/nonaktif, ubah SSID/password, Hide, Max Clients, Isolation/Priority bila dilaporkan ONT); halaman Overview; kolom Model, Redaman, dan Username PPPoE di daftar; "Segarkan data"; "Refresh ONT" tanpa reboot; "Tetapkan vendor" untuk merek yang belum dikenal; filter daftar menurut level redaman dan vendor belum dikenal.
  • Task: ringkasan "apa yang dikerjakan" dan tombol Coba lagi pada task yang sama.
  • Redaman optik: asisten penemuan sumber optik (path tidak ditebak: kandidat dikenali dari parameter yang benar-benar dilaporkan ONT, dipetakan per model oleh SUPERADMIN); penyegaran PPPoE berkala; notifikasi OPTICAL_ALERT (waspada di bawah −25 dBm, kritis di bawah −27 atau di atas −8 dBm) dan webhook DEVICE_FAULT.
  • Dashboard: wawasan armada — mode PON, kualitas optik RX, suhu ONU, uptime, lama offline — dengan tautan ke daftar perangkat terfilter.
  • Data dan katalog: vendor Optictimes beserta OUI dan model (migrasi 0035); jenis notifikasi OPTICAL_ALERT (migrasi 0036); hapus paket langganan (soft delete); value_scale pada API mapping.
  • Operasional: pembersihan data uji (backup tersedia), checklist Excel 55 test case, perbaikan tampilan Langganan & Tagihan dan Riwayat Konfigurasi.

Seluruh fitur tambahan sore hari (asisten optik, filter, peringatan, dashboard) lulus di simulator dan MariaDB nyata, tetapi belum diuji di ONT fisik.

5. Belum diuji dan risiko terbuka

  • Uji tulis lanjutan di ONT fisik: aktif/nonaktif SSID, Hide SSID, Max Clients, pengembalian SSID asli, ubah interval Inform.
  • Uji tulis di F609 dan Optictimes — belum pernah.
  • Connection Request ke ZTE F660/F609 (biasanya meminta Digest; kredensial CR belum diisi di ACS) dan penolakan kredensial CR salah.
  • Diagnostik Ping — gagal 9002 sebelum perbaikan T-07; belum diulang lewat "Coba lagi" (T-16).
  • Redaman optik ZTE dan suhu ONU — dashboard menampilkan "Tidak diketahui" sampai mapping per model ditemukan lewat asisten optik.
  • Stabilitas jangka panjang (Periodic Inform berhari-hari), audit trail, sesi tidak menumpuk — belum dinilai.
  • Sengaja tidak diuji: factory reset, firmware upgrade, push kredensial PPPoE pelanggan asli, aksi massal ke banyak perangkat, kompatibilitas selain tiga ONT di atas (28 vendor katalog lain masih data awal tanpa uji perangkat).
  • Ditunda dengan sengaja: aksi massal tulis dengan pratinjau (berisiko sebelum uji tulis fisik dinyatakan aman) dan ekspor/impor hasil UAT.

6. Pemulihan lingkungan (wajib sebelum UAT ditutup)

  • Kembalikan setelan TR-069 ketiga ONT ke ACS Telkom (acs.telkom.net:9090, interval 43200); pastikan password ACS Telkom diketahui lebih dulu (T-14).
  • Nyalakan lagi Windows Firewall dan tambahkan rule masuk khusus TCP 17547 (T-03).
  • Ganti atau nonaktifkan akun e2e-super yang memakai password uji (T-15).
  • Matikan sleep/Modern Standby laptop selama sesi uji berikutnya (T-17); gunakan IP tetap atau reservasi DHCP (T-04).
  • Kembalikan SSID asli ZTE F660 #2 (SSID2, nonaktif) bila perlu (WR-02).
  • Putuskan pembersihan task lama yang masih menyimpan password plaintext (T-12).

7. Rekomendasi langkah berikutnya

  1. Selesaikan pemulihan lingkungan (bagian 6) — risiko operasional tertinggi.
  2. Jalankan asisten sumber redaman optik pada ZTE F660 dan Optictimes (telusuri cabang WANDevice, cocokkan nilai dengan GUI ONT, simpan mapping per model).
  3. Ulangi task Ping lewat "Coba lagi", lalu uji tulis bertahap di F660 → F609 → Optictimes, selalu dengan pengembalian nilai asli.
  4. Isi kredensial Connection Request ZTE dan uji "Refresh ONT" pada F660/F609.
  5. Setelah butir 2–4 terbukti, nilai ulang apakah aksi massal tulis (dengan pratinjau) aman dikerjakan.
  6. Putuskan kebijakan data uji e2e: pisahkan lingkungan uji dari lingkungan UAT agar daftar perangkat tidak tercemar.
